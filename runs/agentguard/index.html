Why this exists

Tool-using agents — email, calendar, document, CRM access — are vulnerable to indirect prompt injection: instructions hidden in the content they process, hijacking them into actions no one typed. The four public benchmarks that measure this (AgentDojo, InjecAgent, Agent Security Bench, BIPIA) score a defense against a fixed — or originally-fixed — set of known attacks. That score says nothing about resilience against an attacker willing to iterate.

A joint NIST / UK AI Security Institute human red-teaming exercise on an AgentDojo-derived environment found hijack success rise from 11% against generic attacks to 81% against attacks adapted to the specific target — a 7x jump, on the same system. The gap is real. The question a security team actually has to answer isn't "does a static scan find problems" — it's "how does my specific deployed defense hold up against someone who adapts, and what does that protection cost me in blocked legitimate work."

How it works

One configurable red-team agent. Four defense configurations. One matched budget. One report.

01
Configure
Point AgentGuard at a staging deployment of your agent; pick which defenses to compare.
→
02
Attack
A feedback-only adaptive attacker (adopts AutoDojo's published technique) runs the same round budget against each defense.
→
03
Observe & Adapt
Every round's outcome — and every interleaved legitimate request — is logged per defense, independently.
→
04
Report
Final-window ASR and utility-under-attack, per defense, side by side, at equal budget.
The one rule that makes it different: every defense is tested at the same attack budget, in the same campaign — so the comparison can't be gamed by running one defense longer than another, and the attacker never knows which defense it's facing (feedback-only: pass/fail per round, nothing else — the threat model a real attacker actually has).

3. The economics hold, on paper

The single test that settles this

If the matched-budget test finds no meaningful ASR gap between an adaptive attacker and random draws from a static attack set at equal budget, the entire premise collapses — a static benchmark would already be enough. What if I don't buy it?

How do I know your adaptive attacker is representative of a real attacker, not just gaming your own report?

The attacker is AutoDojo's published, peer-reviewed black-box optimizer — not an opaque in-house claim — and the matched-budget design means the comparison can't be gamed by running one defense longer than another. Full methodology: the whitepaper.

You have zero customers and no implementation yet — why should I trust anything here?

Because it's stated plainly instead of hidden. This is a CMPE 295A/295B graduate capstone project — a 4-person team, two semesters — not an operating company. The near-term evidence plan is a specific, cheap, falsifiable test, not a customer logo. See the full list of what's assumed vs. confirmed.

Isn't Adversa AI already doing this?

Adversa AI is the closest commercial competitor, and its existence is confirmed, not a rumor — its engagements are proprietary and per-customer, though, which structurally can't produce a published, standing comparison the way this platform's methodology does. Full positioning analysis.

Won't Microsoft just ship this as a Foundry feature?

Possibly — it's named as the single biggest platform-level risk in this pack, not glossed over. See the dominant-risk analysis.
