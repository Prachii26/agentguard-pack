# Experiment Board

**What this is**: the Blank-style learning log for AgentGuard's ten highest-priority testable hypotheses — the riskiest-assumption test plus all nine `strategy/business_model_canvas.md` block hypotheses — each with an experiment design and a pass/fail threshold declared before any result exists.

**Why it exists**: `strategy/business_model_canvas.md` already states nine falsifiable hypotheses and their cheapest kill-tests in prose; this document is what turns those into a single log format Result/Learning/Decision columns can actually be filled into as tests run, so nothing gets re-litigated from scratch once real data exists. The failure this document prevents: a test running informally, its outcome discussed in a meeting, and no record surviving to the next phase — exactly the "validate demand" red flag `skills/startup-validation`'s own contract warns against, restated here as ten specific, numbered commitments instead.

**How to read it**: the Pass/fail threshold column is the discipline — every row states a number in advance. Result, Learning, and Decision are intentionally blank/"planned" throughout this version: **no experiment on this board has run.** A skeptic should treat any row that looks like it's been quietly pre-answered as a violation of this board's whole purpose.

**Depends on / feeds**: draws directly from `BRIEF.md`'s Riskiest assumption section and all nine hypothesis/test pairs in `strategy/business_model_canvas.md`. Feeds `validation/pivot_log.md`'s standing criteria and, once it exists, `financials/revenue_build.md`.

## Recommended next 3

1. **Run row 1 first, in isolation, before rows 2–10 start** — it is the only row where a fail (per `BRIEF.md`) means the other nine may not be worth running at all; sequencing this board any other way risks investing conversion-funnel and pricing-experiment effort into a wedge that doesn't hold.
2. **Rows 2, 4, 6, and 10 all require a shipped free-tier product to run** — none can start before `strategy/gtm.md`'s day-30 go/no-go gate passes. Do not mark these "in progress" prematurely; they are correctly blocked, not forgotten.
3. **Confirm the row-1 N (proposed as 50, flagged as an assumption, not a founder-set figure) with the founder before the test actually runs** — a wrong N changes both the cost estimate and the statistical meaningfulness of the 10-point pass threshold, and this is cheap to fix now versus after money and two weeks are spent.
