# Capability table — enabling technology, state of the art as of 2026-09-09

**What this is**: a capability-by-capability table of the technology AgentGuard's mechanism depends on — attack generation, defense types it must evaluate against, and the cost/latency substrate — each mapped to the best current system, its measured performance, and the gap that remains.

**Why it exists**: BRIEF.md's "why now" argument rests on two claims — LLM inference got cheap enough to automate adaptive attack generation, and defenses that look strong under static evaluation are a solved-enough category to be worth testing adaptively. Both need real, dated numbers, not a vibe. The failure this document prevents: a whitepaper that asserts "inference is cheap now" without a number, or claims a defense type is well-instrumented when its published false-positive rate is self-reported and unverified.

**How to read it**: the Gap column is the point — it is what AgentGuard's own riskiest-assumption test (BRIEF.md) has to produce evidence about, and what `tech/whitepaper.md` will need to argue around.

**Depends on / feeds**: built from `research/sources.md`. Feeds `research/survey.md` (enabling-technology section) and `tech/whitepaper.md` / `tech/architecture/` directly.
