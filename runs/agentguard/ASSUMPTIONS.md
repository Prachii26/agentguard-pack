## Decisions settled this correction round (founder-specified directly, not open assumptions)

These were gaps in the original brief that the founder closed with explicit instructions rather than leaving to agent judgment. Recorded here so downstream phases know they are fixed, not still-open questions.

- **Threat model**: feedback-only (red-team agent sees only per-round pass/fail, not the defense identity) is the *primary* evaluation mode, because that is what a real attacker actually faces. White-box (defense type known up front) is an upper-bound *comparison condition* only — never reported as if it were the headline result. See BRIEF.md Vocabulary.
- **Riskiest-assumption test design**: matched-budget comparison — N adaptive rounds vs. N random draws from the static attack set, same target, same defense, same total attempts — reporting the ASR gap at equal N. The original N-adaptive-rounds-vs-1-static-attack design was invalid (the adaptive arm would win on volume alone and prove nothing about adaptation itself). A null or negative gap is an explicitly valid, reportable outcome.
- **Metrics set**: final-window ASR (last *k* rounds) is the headline metric, not campaign-average ASR, because early exploration failures in a campaign are the expected shape of adaptation, not a defect to average away. Attempts-to-first-success is reported alongside as a practicality signal. Utility (legitimate task completion under attack, aligned with AgentDojo's definition) is added as a required metric distinct from benign block rate, so the security/usability trade-off is visible rather than asserted.
